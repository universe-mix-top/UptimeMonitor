# UptimeMonitor

**UptimeMonitor** — система мониторинга доступности веб-ресурсов на основе Telegram-бота и REST API. Система периодически проверяет указанные URL-адреса, фиксирует HTTP-коды ответов и время отклика, а также предоставляет пользователям интерфейс для управления списком мониторов и просмотра истории проверок через Telegram.

## 🏗 Архитектура

Проект состоит из трёх независимых компонентов:

```
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│  Telegram Bot   │    │   REST API       │    │ Background Job  │
│  (aiogram)      │    │  (FastAPI)       │    │  (APScheduler)  │
└────────┬────────┘    └────────┬─────────┘    └────────┬────────┘
         │                      │                       │
         └──────────────────────┼───────────────────────┘
                                │
                    ┌───────────▼───────────┐
                    │  Foreground Facade    │
                    │  (db_controller)      │
                    └───────────┬───────────┘
                                │
                    ┌───────────▼───────────┐
                    │     PostgreSQL        │
                    │       (app)           │
                    └───────────────────────┘
```

- **Background** — фоновый модуль, который периодически опрашивает URL-адреса и записывает результаты в БД.
- **Foreground** — слой-фаçад над контроллером БД, используемый как API, так и Telegram-ботом.
- **REST API** — HTTP-интерфейс для программной регистрации, управления мониторами и получения логов.
- **Telegram-бот** — интерактивный CLI с FSM-диалогами для управления мониторами и просмотра логов.

## 📦 Установка

### Предварительные требования

- Python 3.10+
- PostgreSQL 12+

### Шаги

1. **Клонируйте репозиторий:**

   ```bash
   git clone <repository-url>
   cd UptimeMonitor
   ```

2. **Установите зависимости:**

   ```bash
   pip install -r app/core/requirements.txt
   ```

3. **Настройте базу данных:**

   ```sql
   -- Создайте базу данных
   CREATE DATABASE uptimemonitor;
   
   -- Создайте схему
   CREATE SCHEMA app;
   
   -- Примените DDL-схему
   -- Откройте файл app/db_controller/DDL app.sql и выполните его в pgAdmin или psql
   ```

4. **Создайте файл конфигурации:**

   ```bash
   cp app/core/config.ini.example app/core/config.ini
   ```

   Затем отредактируйте `app/core/config.ini` (см. [Конфигурация](#конфигурация)).

## 🚀 Запуск

Проект состоит из трёх независимых компонентов, каждый из которых запускается отдельно.

### 1. Telegram-бот

```bash
python app/tgbot/run_tg_bot.py
```

Запускает Telegram-бота в режиме long-polling. Подключается к PostgreSQL при старте и отключается при завершении.

### 2. REST API

```bash
uvicorn app.modules.run_api:app --host 0.0.0.0 --port 8000 --reload
```

Запускает REST API на `http://localhost:8000`.

**Документация API (Swagger UI):** `http://localhost:8000/docs`

### 3. Фоновый мониторинг

```bash
python app/modules/background/background.py
```

Запускает APScheduler с `AsyncIOScheduler`, который проверяет мониторы каждые 10 минут (Cron: `minute='*/10'`).

> **Примечание:** Все три компонента могут работать одновременно и независимо друг от друга, подключаясь к одной базе данных.

## 🌐 REST API

**Базовый URL:** `http://localhost:8000`

### Регистрация пользователя

```
POST /register?tg_id={tg_id}
```

Регистрирует пользователя по Telegram ID.

**Ответ:**
```json
{
  "tg_id": 123456789,
  "user_id": 1,
  "is_new_user": true
}
```

### Управление мониторами

#### Добавить монитор

```
POST /background/monitor?tg_id={tg_id}&url={url}&timing_id={timing_id}
```

**Параметры:**

| Парамет    | Тип    | Описание                        |
|------------|--------|---------------------------------|
| `tg_id`    | int    | Telegram ID пользователя        |
| `url`      | str    | URL для мониторинга             |
| `timing_id`| int    | ID интервала (1-5)              |

#### Изменить интервал монитора

```
PUT /background/monitor?tg_id={tg_id}&url={url}&timing_id={timing_id}
```

#### Удалить монитор

```
DELETE /background/monitor?tg_id={tg_id}&url={url}
```

### Получение интервалов

```
GET /background/timings
```

**Ответ:** Список доступных интервалов мониторинга.

### Получение логов

#### Список мониторов пользователя

```
GET /logs/monitors?tg_id={tg_id}
```

**Ответ:** Список URL с описаниями интервалов.

#### Логи для конкретного URL

```
GET /logs/user/{tg_id}?url={url}
```

**Ответ:** История проверок для указанного URL.

## 🤖 Telegram-бот

### Команды

| Команда | Описание                                      |
|---------|-----------------------------------------------|
| `/start` | Регистрация пользователя, приветственное сообщение |
| `/q`     | Возврат в главное меню из любого состояния    |

### Главное меню

Кнопки главного меню:

| Кнопка                                  | Описание                              |
|-----------------------------------------|---------------------------------------|
| **открыть логи опросов**                | Просмотр истории проверок URL         |
| **мой список сайтов**                   | Список всех мониторов с интервалами   |
| **настройка списка сайтов в списке опроса** | Подменю: добавить/изменить/удалить |

### FSM-диалоги

#### Добавление монитора

```
[настройка списка сайтов...] → add → Введите URL → Введите интервал (число 1-5 или текст)
```

#### Изменение интервала

```
[настройка списка сайтов...] → change → Выберите URL → Выберите новый интервал
```

#### Удаление монитора

```
[настройка списка сайтов...] → del → Выберите URL → Подтвердите удаление
```

#### Просмотр логов

```
[открыть логи опросов] → Выберите URL (по номеру или названию) → Показать логи
```

### Интервалы мониторинга

| ID | Описание   | Частота       |
|----|------------|---------------|
| 1  | 10 минут   | Каждые 10 мин |
| 2  | 30 минут   | Каждые 30 мин |
| 3  | 1 час      | Каждые 1 час  |
| 4  | 3 часа     | Каждые 3 часа |
| 5  | 6 часов    | Каждые 6 часов|

### Валидация ввода

- **URL:** Проверяется по regex-паттернам (поддержка доменных имён и IP-адресов).
- **Интервал:** Принимается как число (1–5), так и текстовое описание («10 минут», «1 час» и т.д.).

## 🗄 База данных

### Схема `app`

#### Таблица `users`

Хранит информацию о пользователях Telegram.

| Колонка     | Тип        | Описание                   |
|-------------|------------|----------------------------|
| `user_id`   | SERIAL     | Автоинкрементный PK        |
| `tg_id`     | BIGINT     | Telegram ID (UNIQUE)       |

#### Таблица `timings`

Доступные интервалы мониторинга (предзаполнена).

| Колонка     | Тип       | Описание                   |
|-------------|-----------|----------------------------|
| `timing_id` | SERIAL    | Автоинкрементный PK        |
| `interval`  | INTEGER   | Интервал в минутах         |
| `description`| TEXT     | Текстовое описание         |

#### Таблица `urls`

Уникальные URL-адреса для мониторинга.

| Колонка     | Тип       | Описание                   |
|-------------|-----------|----------------------------|
| `url_id`    | SERIAL    | Автоинкрементный PK        |
| `url`       | TEXT      | URL-адрес (UNIQUE)         |

#### Таблица `monitors`

Связывает URL с интервалом мониторинга.

| Колонка     | Тип       | Описание                   |
|-------------|-----------|----------------------------|
| `monitor_id`| SERIAL    | Автоинкрементный PK        |
| `url_id`    | INTEGER   | FK → urls.url_id           |
| `timing_id` | INTEGER   | FK → timings.timing_id     |

#### Таблица `monitors_presets`

Многие-ко-многим: какие пользователи мониторят какие мониторы.

| Колонка         | Тип     | Описание                        |
|-----------------|---------|---------------------------------|
| `user_id`       | INTEGER | FK → users.user_id              |
| `monitor_id`    | INTEGER | FK → monitors.monitor_id        |

#### Таблица `requests_log`

История каждой HTTP-проверки.

| Колонка       | Тип         | Описание                      |
|---------------|-------------|-------------------------------|
| `log_id`      | SERIAL      | Автоинкрементный PK           |
| `datetime`    | TIMESTAMP   | Дата и время проверки         |
| `url_id`      | INTEGER     | FK → urls.url_id              |
| `timing_id`   | INTEGER     | FK → timings.timing_id        |
| `res_code`    | INTEGER     | HTTP status code              |
| `ping_ms`     | REAL        | Время отклика (мс)            |

## 📝 Примечания

- **Кэширование:** Контроллер БД использует `TTLCache` (из `cachetools`) для `user_cache`, `url_cache` и `monitor_cache` с лимитом 1024 записей и TTL 600 секунд.
- **Ограничение параллелизма:** Фоновый checker использует `asyncio.Semaphore` (по умолчанию 50) для ограничения одновременных HTTP-запросов. Настраивается в `config.ini` → `[Requester]simultaneous_requests`.
- **Язык интерфейса:** Интерфейс Telegram-бота и сообщения выполнены на русском языке.
- **Перенаправления:** HTTP-запросы следуют за редиректами (redirects enabled).
